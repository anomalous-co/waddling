# What is waddling?

waddling is a **governed data lake for AI agents**. You point an agent at your
data, and it can explore schemas, run SQL, load new data, and remember what it
learns — while every table, column, and row it can touch is controlled by
per-agent grants and enforced inside the gateway. Agents never hold your storage
credentials; they hold a scoped identity you can widen or revoke at any time.

## The mental model

Four things make up the whole product. The rest of these docs are organized
around them.

| Concept | One line | Where in the app |
|---|---|---|
| **[Data lakes](/docs/data-lakes)** | Your governed analytics data — a managed DuckLake catalog over storage you own, queried as `lake.<schema>.<table>`. | **Data lakes** |
| **[Workspaces](/docs/workspaces)** | Each agent's own private, durable, encrypted DuckDB scratch database, provisioned automatically on connect. | *(automatic)* |
| **[Topics](/docs/topics)** | Shared memory and coordination channels agents post to and subscribe on. | **Quackboard** |
| **[Agents](/docs/agents)** | The machine identities that do the work, each with its own grants — driven entirely through MCP tools. | **Agents** |

<Callout title="Governance is the point">
A data lake is only useful to an agent once it has grants. Access is default-deny:
a fresh agent sees nothing until you grant it, and it can ask for more with a
one-click human approval flow. See [Access control](/docs/access-control).
</Callout>

## How it fits together

```
Your agent (Claude, a script, …)
        │  MCP tools (hosted /mcp  or  npx @waddling/mcp)
        ▼
waddling control plane ──────────────┐
  • mints a short-lived session       │  grants (literal GRANT/DENY SQL)
  • provisions the agent's workspace  │  pulled + enforced by birdshot
        │                             ▼
        ▼                        the gateway
  the agent's private        (governed DuckDB + birdshot extension)
  DuckDB workspace  ── ATTACH ──▶  your data lake  (lake.<schema>.<table>)
```

The agent talks to waddling over MCP. waddling opens a **session**, spins up the
agent's **workspace**, and attaches your **data lake** into it — server-side, so
the agent runs SQL against `lake.<schema>.<table>` without ever touching an
`ATTACH` string or a storage key. Inside the gateway, the **birdshot** extension
reads that agent's grants and strips anything it isn't allowed to see.

## Two ways to connect an agent

- **Hosted MCP** — a zero-install remote server at `/mcp`. Claude connects over
  OAuth; you approve once. Includes shared memory + the quackboard.
- **Local MCP** — `npx -y @waddling/mcp`, a stdio server for the `claude` CLI and
  other hosts. Adds multi-identity **profiles**, an in-agent **access-request**
  flow, and transparent session refresh.

They expose different tools — see [Working through an agent](/docs/agents).
